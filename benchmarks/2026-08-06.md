# tq migration report

This report compares `jq`, `yq`, and `tq` on the same JSON commands. The main
results use a frozen monthly USGS feed: 7.35 MiB and 10,847 records.

## Monthly JSON results

Every applicable command passed the same correctness check. Time is the median
wall-clock time. RSS is the maximum observed peak resident memory. Every delta
is relative to jq. `yq` has no matching event-stream mode.

## What a migration user can expect

- tq is near jq for numeric reduction and scalar reads.
- tq is faster for document update and re-encoding.
- tq is slower for object construction and full JSON event streams.
- tq uses about twice jq's RSS for most non-stream commands in this test.
- yq uses much more memory than jq or tq for these JSON commands.
- See [feature support](../tests/compatibility/README.md) before moving a filter.

## Test limit

The hourly, daily, weekly, and monthly matrices completed. The large profile
is not run for now. A prior multi-input run failed with `No space left on
device` in the macOS temporary directory and coincided with excessive editor
memory use. The harness now writes command output to temporary files. Timed
output is deleted on success; failed output is retained for investigation.
Correctness output is also file-backed and has a 32 MiB limit. Do not use the
older large-file figures for a migration decision until the large-output
correctness check is streaming.
