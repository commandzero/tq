The run uncovered two more runner constraints. On macOS, process-group
RSS must be sampled from `ps -axo pgid=,rss=`; `ps -g` selects a user group and
cannot enforce the cap. Also, large semantic result normalization can retain a
multi-gigabyte in-process sequence even when the file-backed output boundary is
32 MiB. The runner now converts an oversized reference correctness capture
into bounded per-adapter resource rows, but streaming semantic digests remain
necessary for useful timed output-heavy comparisons.

This frozen replay provided the complete safe failure matrix needed to diagnose
the release gate without hiding any tool or format row. It was followed by the
newly recollected campaign below.

## Optimized natural-large event release gate

Profiling identified the dominant stream cost: every jq-style event record
constructed a fresh VM whose general pull path started and joined a worker
thread. The VM now exposes synchronous exhaustive consumption for callers that
already drain every result. Pull-based `next_result` behavior remains available
for demand-driven callers, while the stream executor avoids thread-per-record
startup and preserves the same managed evaluator limits.

On the 7,567,881-byte standard all-month input, a one-sample A/B check reduced
tq/JSON from 19.19 seconds to 2.67 seconds and tq/TOON from 11.69 seconds to
0.56 seconds. jq/JSON measured 0.28 seconds. The optimization changed execution
overhead, not the event decoder, query, input, or normalized result contract.

large event case against the refreshed manifest. It used the case's 600-second
